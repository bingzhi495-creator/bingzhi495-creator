# Skill: Skills for Skills

## Purpose

Turn professional knowledge found in GitHub repositories, documentation, examples, and public learning resources into reusable, well-bounded Skills.

This skill is designed for building more skills. It helps transform scattered expert knowledge into structured learning and execution patterns that can be reused by educators, developers, curriculum designers, and AI-assisted workflows.

## What This Skill Is For

Use this skill when you want to:

- Convert a GitHub project into a reusable teaching or workflow skill.
- Extract professional patterns from documentation, examples, issues, and repository structure.
- Turn expert practice into a clear step-by-step method.
- Build skill files that are useful, safe, and easy to maintain.
- Create education-focused skills without exposing private identity, student information, paid-service claims, or income-related details.

## Inputs

A good skill-building task usually starts with one or more of the following:

- A GitHub repository URL
- A documentation site
- A technical tutorial
- A project README
- A set of examples or notebooks
- A workflow already used in teaching or practice
- A professional domain topic that needs to become reusable guidance

## Core Principle

Do not copy a repository. Extract the reusable pattern behind it.

A good Skill should describe how to think, decide, act, verify, and revise within a domain. It should not simply summarize source material or list links.

## Workflow

### 1. Define the Skill Target

Clarify what the new Skill should help someone do.

Useful questions:

- Who will use this Skill?
- What task should it make easier?
- What decisions does the user need to make?
- What output should the Skill help produce?
- What risks or boundaries must be respected?

### 2. Inspect Source Knowledge

When studying a GitHub repository or documentation source, look for reusable professional knowledge:

- Project structure
- Naming conventions
- Setup workflow
- Core concepts
- Common tasks
- Example inputs and outputs
- Evaluation or testing methods
- Failure modes
- Security, privacy, or ethics notes
- Maintenance patterns

### 3. Extract Patterns

Convert raw source details into generalizable patterns.

Examples:

- A README installation section becomes a setup checklist.
- A tutorial sequence becomes a learning path.
- A test suite becomes a verification strategy.
- Issue discussions become common troubleshooting cases.
- Example projects become reusable classroom activities.
- Documentation conventions become a resource-production template.

### 4. Separate Facts From Guidance

A Skill should distinguish:

- Facts: What the source says or demonstrates.
- Inference: What pattern can be learned from it.
- Guidance: How someone should apply the pattern.
- Boundary: What the Skill should not claim or expose.

This keeps the Skill useful without overstating evidence.

### 5. Write the Skill Structure

Use a stable structure so Skills are easy to scan and reuse.

Recommended sections:

- Title
- Purpose
- When to Use
- Inputs
- Workflow
- Typical Outputs
- Quality Checklist
- Public Boundary
- Maintenance Notes

### 6. Add Domain Boundaries

Every Skill should include boundaries that prevent misuse.

For education skills, boundaries may include:

- Do not expose student identities or private records.
- Do not imply school endorsement without permission.
- Do not promise competition results, admissions outcomes, or income benefits.
- Do not publish internal paid materials or confidential resources.
- Do not encourage academic dishonesty or AI-assisted replacement of student work.

For technical skills, boundaries may include:

- Do not expose secrets, tokens, keys, or private infrastructure.
- Do not recommend unsafe commands without verification.
- Do not copy licensed content without permission.
- Do not turn examples into production claims without testing.

### 7. Verify the Skill

Before publishing a Skill, check whether it is:

- Actionable: Can someone follow it?
- Specific: Does it help with a real task?
- Reusable: Can it apply beyond one source?
- Bounded: Does it avoid overclaiming?
- Safe: Does it avoid private, risky, or misleading content?
- Maintainable: Can it be updated when source knowledge changes?

## Typical Outputs

This Skill can produce:

- A new Skill draft
- A Skill topic index
- A domain workflow checklist
- A teaching activity guide
- A resource-production template
- A rubric for evaluating Skills
- A maintenance plan for a Skill library

## Skill Quality Rubric

| Dimension | Strong Skill Looks Like |
| --- | --- |
| Purpose | The task and user are clear. |
| Workflow | Steps are concrete and ordered. |
| Outputs | Expected artifacts are named. |
| Evidence | Source patterns are transformed, not copied blindly. |
| Boundaries | Privacy, ethics, and claim limits are explicit. |
| Reuse | The Skill can work across similar situations. |
| Maintenance | The Skill can be updated as tools and practices change. |

## Example Prompt

Use this prompt to create a new Skill from GitHub knowledge:

```text
Study the provided GitHub repository or documentation. Extract reusable professional knowledge patterns and turn them into a Skill. Do not copy source text. Identify the target user, task, workflow, expected outputs, quality checklist, and public boundaries. If the source includes education-related material, avoid real student information, school-specific claims, admissions promises, paid-service framing, and income-related language.
```

## Public Boundary

This Skill is for educational and professional knowledge organization. It does not claim to train a model, replace expert review, certify professional competence, or create commercial services. It organizes public knowledge into reusable guidance while respecting privacy, attribution, safety, and scope limits.

## Maintenance Notes

Review this Skill regularly as GitHub practices, documentation styles, AI tools, and education technology workflows change. When updating it, preserve the distinction between source facts, inferred patterns, and recommended actions.
